# Decisions

One dated line per decision the owner has made about Odin, newest first, with where
the detail lives. A decision stays here after it is built; when one is reversed, add a
new line at the top and leave the old one (the history is the point). "Where" names a
file or a commit message (`git log --grep`); a decision with no file is recorded here
for the first time.

How to add one: date it, say what was decided and why in a sentence, link the detail.
Dates are the day the owner decided, not the day it shipped; the release it shipped in
is in the change log (Settings → System map & changes).

## October 2026

- **16 Oct**: Moving past a stage gate is for an Admin and, while policy `gate_override` says so (the default), the rollout's project manager, always with a typed reason; it is audited and kept in the stage history as a staff note. The vendor link never overrides, and the customer never sees gate internals. Where: `services/gates.py`, PRODUCT.md "Stage gates".
- **16 Oct**: Automations reach staff and Teams only, never the customer, and never move a stage; a rule's own actions start no other rule (depth 1); only Admins write them. Where: `services/rules.py`, PRODUCT.md "Automations".
- **16 Oct**: Capacity is hours per week (policy default 30, a per-person override on the Users page), from task estimates plus an allowance per managed rollout. Hours and counts only, never money. Where: `services/workload.py`, PRODUCT.md "Workload".
- **16 Oct**: Customer satisfaction is one rating (1 to 5, optional comment) given when the customer signs the sign-off, once per version; it is internal (People, the internal report, the portfolio), never in a customer cut. Where: `services/asks.py`, PRODUCT.md "Customer self-service".
- **16 Oct**: The CRM intake contract: `POST /api/v1/intake` with a token of the `create` scope (which opens nothing else), the deal id as the idempotency key, every key typed and capped, contacts held to the partner domains, a rate limit per token; the result is a pending rollout a project manager confirms with the PO. No vendor connector. Where: `docs/API_V1.md`, `services/intake.py`.
- **16 Oct**: Resend carries sign-in mail only (sign-in links, password resets, address confirmations, invitations), falling back to Microsoft 365 when it refuses; notifications, the digest and reports stay on Microsoft 365. Where: DEPLOY.md "Sign-in mail through Resend", `services/resend.py`.
- **16 Oct**: The outsider task cut: a customer, reseller or contractor sees only the tasks assigned to them (their asks), on the rollout, the flow and in mail, never the team's tasks. Where: `services/asks.py`, `routes/api.py` (the flow detail), PRODUCT.md "Customer self-service".
- **16 Oct**: Dependencies are finish-to-start between tasks of one rollout, never a loop; template tasks bring roles, due offsets and one link each. No full critical path. Where: `services/task_links.py`, `services/template_tasks.py`.
- **16 Oct**: `/api/v1/projects` pages with `limit` (1 to 500) and `offset` when asked; without them it answers the whole set, as before, plus a `total`. Where: `docs/API_V1.md`.

- **15 Oct**: A release that adds a table, column, permission or alert type raises `db.SCHEMA_VERSION`; older code on a newer database skips its destructive boot steps, so the updater's rollback is safe. Where: CLAUDE.md "Adding a table", `db.py`.
- **15 Oct**: Dev and UAT listen on 127.0.0.1 only (set `HOST` to open them) and keep a private key in `DATA_DIR/secret_key` when no `SECRET_KEY` is set. Where: CLAUDE.md "Adding a table".
- **13 Oct**: v1.7.0 (design round 2, the alias, the Odin PMS Teams app, then the Flow views) is held on `dev` until the owner says go; it was released on 14 Oct (tag `v1.7.0`, hand-tagged because CI could not start). Where: `git show v1.7.0`, `docs/review-2026-10-14.md`.
- **13 Oct**: Kanban, Gantt and Calendar are views of the Flow beside the list, which stays the default (this overrode the 8 Sep rejection of kanban-style boards for the list itself). The Kibana view is removed. Where: DESIGN.md "Flow views".
- **13 Oct**: Teams notifications come from a notification-only "Odin PMS" Teams app, as a card in each staff member's own chat, because the shared `notifications@` mailbox has no Teams alias. Partners and customers get email only. No buttons on cards. Where: `services/teams_bot.py`, Settings → Integrations, PRODUCT.md "Notifications".
- **13 Oct**: Odin's Microsoft 365 connection is the dedicated mailbox `notifications@`, shared with other in-house systems; mail shows the alias `Odin-PMS@` (policy `mail_from`). Where: AZURE_SETUP.md, `graph.py`, Settings → Notifications.
- **12 Oct**: Health reads in plan words only: On track / At risk / Off track (and Complete), with the reason as detail. Red also marks a declined approval or sign-off, an open blocker and a critical alert, and nothing else. Where: DESIGN.md "The Plan Words Rule", "Allowed reds".
- **12 Oct**: The UI says "rollout" wherever a person reads about the work; "project" stays for the record and its form, the "Project manager" role, URLs, API fields and template tokens. Where: PRODUCT.md "Terminology".
- **10 Oct**: Odin is built for desktop (about 90% of users) and for English only: phone-only findings are out of scope, and there is no translation, RTL or other-language work. Where: here; `docs/review-plan-2026-10-14.md` triages by it.

- **9 Oct**: The Jinja UI is retired: every signed-in page is React. Still Jinja: the guest pages, the sign-in fallback, the error page. Where: CLAUDE.md "Front end", commit "Retire the Jinja UI".
- **9 Oct**: UI/UX rules: six type sizes (11-24 px), the 4/8 px grid, no card inside a card, dark depth by tone, buttons with a loading state, inline field errors, toasts for silent saves, receipt rows. Plus the refresh: pastel accents, straight segmented progress bar, a 72 px header with Log out in the avatar menu, tooltips. Where: DESIGN.md "UI/UX rules", "The 9 Oct 2026 refresh".
- **9 Oct**: The map generator refuses an uncommitted `VERSION`: set `VERSION` and commit it first, then regenerate the system map (v1.5.0 shipped a stale map). Where: CLAUDE.md "System map".
- **8 Oct**: AI is a local framework: one OpenAI-compatible server on the office LAN (alias P24-AI, shared with the company CRM, managed outside this repo); everything about it is a policy; a feature runs only when AI is on, the server is up, the feature is on and it passed validation on the current model and prompt; the model never decides, sends or moves anything; it is never called from a web request; nothing outside `services/ai/` talks to the server; a non-private address is refused unless an admin allows it. Output is a suggestion a person accepts through the normal audited route. Where: CLAUDE.md "AI framework", `services/ai/`.
- **8 Oct**: Fourteen AI features and a lessons library built in one go (weekly words, risks proposed, why amber, portfolio narrative, sign-off summary, customer words, SOW to plan, chase drafts, morning brief, catch me up, SLA calibration, ask this rollout, meeting notes to tasks, lessons). Search is plain keyword search, not embeddings (the server has no embedding model). Where: `services/ai/features/`, PRODUCT.md "AI".
- **8 Oct**: Four bottleneck alerts join the four lifecycle alerts (approval waiting, blocker open, task with no owner, customer task overdue), each with its own wait in days. Where: `constants.ALERT_TYPE_TITLES`.
- **6 Oct**: The Odin 2.0 plan (custom fields, stage gates, dependencies, customer self-service, milestones and recurring work, rules, workload, a CRM intake endpoint) is one release, v2.0.0, built workstream by workstream with a UAT check after each; it was put on hold while the local-AI work was decided and has not been started. The CRM is in-house, so Odin offers an intake endpoint and no vendor connector. Still out: commercials, a marketplace, a mobile app, a full critical path.

## September 2026

- **30 Sep**: Branches and releases: all work on `dev`, never straight to `main`; a pull request dev to main that raises `VERSION` is the release (merge commits, not squash); CI tags it; the production server's cron job moves itself to the newest tag, with backup and rollback. Where: CLAUDE.md "Branches and releases", DEPLOY.md, `deploy/odin-update.sh`.
- **30 Sep**: Odin goes live at odin.protect24x7.com on a Proxmox VM, with `cloudflared` on the host as on the Zeus server and no Cloudflare Access. Where: `docs/GO_LIVE.md`, `docs/RUNBOOK.md`.
- **30 Sep**: Scope and sign-off close every rollout: a Sign-off stage before the last stage, an e-signature the customer signs and we countersign, frozen as canonical JSON with a SHA-256 fingerprint. The last stage cannot be reached until it is complete, unless an admin waives it with a written reason. Where: `services/signoff.py`, PRODUCT.md "Scope and sign-off".
- **30 Sep**: Plan, baseline and RAID: the first plan save freezes the baseline, every move after it carries a reason; a rollout report in an internal and a customer cut, and a portfolio report, both as PDF. The customer cut is made on the server. Where: PRODUCT.md, `services/report_data.py`.
- **30 Sep**: Stage lengths and SLAs count working days (public holidays in Settings); gaps between dates stay calendar days. Where: CLAUDE.md "Admin settings", `services/workdays.py`.
- **30 Sep**: The settings gap round: sign-up links and time-on-Odin tracking get off switches; read notifications and time on Odin are kept for set periods; two-step sign-in (authenticator code and ten recovery codes) for password accounts. Not chosen: locking the dashboard layout. Where: PRODUCT.md, `services/mfa.py`.
- **29 Sep**: The conservative dashboard was rejected; a shared reference is the brief. Result: cards on a tinted ground app-wide, the dashboard as the home page, an admin default layout plus each person's own copy, every widget on by default. Where: DESIGN.md "Creative North Star", "Dashboard".
- **28 Sep**: Staff sign in with Microsoft only, plus a "break-glass" password for accounts an admin flags (every use audited and announced). A first Microsoft sign-in waits for an admin to approve it with a role; Odin decides roles. Partners use an emailed one-time link with a Continue button (so mail scanners cannot spend it). Where: `routes/sso.py`, PRODUCT.md "Staff sign in with Microsoft".
- **28 Sep**: Any value an admin may change is a policy (area, kind, default, limits, label, help) on one categorised Settings page, never a hard-coded number. Where: CLAUDE.md "Admin settings", `policies.py`.
- **28 Sep**: Backups go to OneDrive, a SharePoint folder and/or a network share on an in-app schedule, with retention and an automatic restore test. Declined: S3 or Azure Blob, backup encryption, a Power BI or SharePoint export. API tokens are read-only. Off-host disaster recovery, SCIM, Postgres and a WAF are a separate ops track. Where: DEPLOY.md, PRODUCT.md "Backups", "Read-only API tokens", `docs/API_V1.md`.
- **27 Sep**: The brand is "Odin by Protect24x7": the raven mark, the ODIN wordmark with a red-struck O, the tagline "Every project. On watch." The parent's black, red `#E11D2E` and Chakra Petch live on brand surfaces only; inside the app red means overdue. Where: `docs/BRAND.md`, CLAUDE.md "Visual authority".
- **27 Sep**: Each user picks light, dark or follow the OS and one of the accents; the choice lives on the user row. Never hard-code a colour. Where: CLAUDE.md "Themes", DESIGN.md "Themes and accents".
- **23 Sep**: Project roles bind staff too: only the Project manager moves stages and edits the project; a Coordinator runs tasks and documents; everyone else reads, comments and ticks tasks tagged to them. Admins bypass it. Where: `constants.PROJECT_ACTIONS`, commit "Project roles bind internal staff".
- **22 Sep**: Partners and customers are invited by email and sign in with a one-time link, no password, seeing only their projects; the older anonymous guest links stay until invited accounts replace them (they gained an off switch on 24 Sep and, for v1.8.0, an expiry, `guest_link_days`). Where: PRODUCT.md "Users".
- **19 Sep**: Every project owns its stage list, copied from a template in Settings at creation and then editable. Tasks belong to a stage of their project. Where: PRODUCT.md "Capabilities and Constraints".
- **8 Sep**: A light, direct flowchart UI (convention played straight; craft bar Linear and Whimsical/FigJam), replacing the dark, industrial look. Rejected: metaphorical worlds, Jira/Monday/Asana-style boards as the look, gamification, number-dense tables. The front end is Vite + React + TypeScript + shadcn/ui, with Flask as the JSON API, ported page by page. Where: DESIGN.md, CLAUDE.md "Front end", PRODUCT.md "Brand Commitments".
